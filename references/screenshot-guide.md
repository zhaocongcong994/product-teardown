# 截图采集详细指南（Round 0 参考）

## 各平台截图路径

### 1. Web 端（自动化程度最高，优先）
- 使用浏览器操作工具（如 kimi-webbridge）打开产品，使用用户真实登录会话
- 按拆解计划逐步操作：点击、输入、选择，每步操作后截图
- 覆盖：首页/入口、核心配置、主流程对话或操作、资产产物、账户/会员、失败与错误提示

### 2. 微信小程序
微信小程序没有浏览器 URL，无法用浏览器工具操作。可选路径：
- **微信开发者工具**（推荐）：安装后导入/打开目标小程序，模拟器中可点击、输入操作，配合系统截图截取模拟器窗口。需要用户提前装好并登录有权限的微信账号
- **Mac 版微信**：直接打开小程序窗口，用系统截图 `screencapture` 截取窗口。操作需用户手动配合或系统级自动化
- 自动化程度低于 web，截图前必须人工/回读确认页面状态

### 3. 桌面 App（Mac）
- 产品提供 Mac 桌面版（或 iOS App 可在 Apple Silicon Mac 运行）时可操作
- 截图：系统级窗口截图
- 操作：依赖系统级自动化（如 AppleScript 模拟点击），可靠性一般，关键环节建议用户手动操作、Agent 负责截图与校验

### 4. 能力都不具备时
明确告知用户："我需要一个能够实际操作产品并截图的工具功能才能继续"，停止等待。

## 页面响应确认（防截到未响应页面）

点击/输入操作后，**必须先确认页面已反应，再截图**：
1. 操作后等待合理时间（生成类操作按产品提示的加载状态等待，通常数秒到数十秒）
2. 对比操作前后的页面状态：URL、标题、可见元素、加载指示器是否消失
3. 截图后**回读该截图**，确认内容是操作后的预期页面；如果发现页面没反应（和上一张一样），重新等待并重截
4. 生成类长任务：必须等到生成完成状态出现再截，不能截"生成中"的中间态充当结果（除非记录的就是等待状态本身）

## 去重校验

- 每张新截图与前序截图对比（可用文件哈希初筛 + 回读图片内容确认）
- 画面完全重复（如同一页面误截两次）→ 剔除重复项，只保留一张
- 注意区分"重复"与"同页面不同状态"（如列表新增了资产卡片），后者是有效证据，需保留并在清单中注明状态差异

## 命名规范

`序号-阶段-动作.png`，序号两位起步，例如：
- `01-首页-进入产品.png`
- `03-采访配置-选择主题.png`
- `12-文章生成-生成失败提示.png`

## 图片清单.csv 格式

```csv
序号,文件名,对应操作步骤,页面状态,校验结果
1,01-首页-进入产品.png,打开产品首页,正常加载,与操作一致
```

采集完成后向用户汇报：截图总数、覆盖的流程分支（主流程/纠偏/失败/中断）、缺失或无法截取的部分，确认后进入 Round 1。
