# Round 3：单 Agent 功能等价 System Prompt

对 Round 2 识别出的**每个目标 Agent 各执行一轮**。目标：基于页面真实行为证据，为该 Agent 编写一份"功能等价 System Prompt"——不要求还原官方原文，但应能让另一个 Agent 在相同输入、工具和全局上下文下，表现出接近的工作流程、判断边界、工具调用和交接行为。

## 一、确认目标 Agent 的边界

收集该 Agent 的所有记录，回答：它解决什么问题、从何时接管任务、谁触发、完成后交给谁、哪些工作属于/不属于它、是否会被用户修改意见重新触发、哪些情况必须停止、哪些情况可自动继续、是否需要等待用户确认。

## 二、整理输入契约（六类）

A. 用户当前输入（需求、选择、反馈、修改意见、满意/继续、中断指令、上传素材）
B. 用户长期信息（语言、会员状态、余额、资产库、已保存配置、历史版本、默认偏好）
C. 项目全局上下文（项目基本信息、配置、风格、资产及引用、当前状态、确认状态、模型与参数、历史生成结果）
D. 上游 Agent 输出（上游是谁、传递了哪些字段和资产、哪些输入必须存在才能开始工作）
E. 平台公共信息（风格库/模板、模型能力与限制、领域专业知识、提示词模板、安全/版权/计费规则）
F. 工具与运行时结果（成功/失败结果、安全拦截、额度不足、用户中断、重试结果、状态更新结果）

## 三、整理输出契约（五类）

1. 给用户的自然语言回复；2. 按钮、表单、确认卡片等页面组件；3. 生成的资产；4. 写入全局上下文的结构化字段和状态；5. 传递给下游 Agent 的任务与数据。

## 四、整理工具契约

只使用有页面证据支持的工具；非官方名称必须注明。特别检查：调用前是否需要用户确认、成功后如何验证、失败后是否自动重试、重试是否可能重复扣费或重复创建资产、用户中断后是否继续执行、工具成功但状态写入失败时怎么办。

## 五、整理状态机

将工作过程还原为状态而非自然语言步骤。至少检查：waiting_input、planning、waiting_confirm、executing、validating、completed、failed、interrupted、retrying、handoff（可按实际证据调整）。输出状态表 + 一张 Mermaid 状态图。

## 六、推导 System Prompt 必须包含的规则

每条规则标记来源：【事实规则】【推断规则】【建议规则】（原产品没做好但为稳定工作建议新增）【未知】。规则至少覆盖：Agent 身份、目标、工作边界、输入检查、上下文读写、工作步骤、工具选择与前置条件、用户确认门、结果验证、修改与回退、失败与重试、中断处理、下游交接、完成条件、输出格式。

## 七、编写功能等价 System Prompt（15 节固定结构）

1. **角色**：身份、专业能力、服务对象
2. **核心目标**：最终交付什么
3. **任务边界**：允许/禁止做什么、哪些工作必须交给其他 Agent、何时必须停止并询问用户
4. **输入契约**：六类输入，区分必填与可选
5. **全局上下文协议**：允许读取/写入/禁止修改的字段、字段的生产者和消费者、修改后需失效或重做的下游资产。字段名优先用页面真实名称；页面没有的用语义化占位名并注明属于推导设计
6. **工作流程**：编号步骤，每步写清进入条件、使用的输入、需要做出的判断、是否调用工具、是否写上下文、是否等用户确认、完成后进入哪一步
7. **工具调用规范**：每个工具的调用时机、必填参数、调用前检查、成功/失败结果、是否允许重试及次数、幂等要求、调用后的状态写入。非官方工具用占位名如 `<生成视频工具>`，不要编造看似真实的 API 名称
8. **用户确认机制**：哪些动作必须等待确认（使用生成额度、批量生成、覆盖已有资产、改变已确认内容、进入下游流程）。不得用"你满意吗"代替明确的状态写入
9. **结果验证**：不能只信工具返回的"成功"，必须检查与任务相关的结果（是否遵循指定风格/符合原始需求/资产引用正确/输出资产实际存在/页面状态与聊天状态一致）。验证失败不得声称"严格符合要求"
10. **修改与回退**：局部更新 vs 下游失效范围、保留历史版本、避免直接覆盖已确认资产
11. **异常处理**：输入缺失、工具失败、安全拦截、额度不足、状态写入失败、用户中断、重复请求、下游无法启动。禁止在无证据时声称错误是"随机误判"
12. **状态机**：每个状态下允许和禁止的动作
13. **下游交接**：满足完成条件后才能交接；交接内容含任务状态、已确认输入、资产引用、待处理任务、未解决问题、用户确认记录
14. **完成条件**：必需资产存在 + 上下文写入成功 + 结果验证通过 + 用户确认已记录 + 交接数据完整
15. **输出格式**：按页面证据设计结构化输出；真实格式未知时用语义清晰的建议格式，不冒充官方格式

## 八、规则—证据追溯表 + 最小测试集

- 追溯表：System Prompt 中每条规则 ↔ 对应证据/推断/建议来源
- 最小测试集（≥6 个）：正常输入完整、缺少必要输入、用户修改局部内容、工具调用失败、用户中断任务、全局上下文与页面状态冲突。每个测试含：测试输入、初始状态、预期判断、预期工具调用、预期状态变化、不允许出现的行为

## 九、交付顺序（每个 Agent 一份 HTML）

1. 目标 Agent 的证据范围 → 2. 输入契约 → 3. 输出契约 → 4. 工具契约 → 5. 状态机（含 Mermaid 图）→ 6. 事实/推断/建议规则 → 7. 功能等价 System Prompt → 8. 规则—证据追溯表 → 9. 最小测试集 → 10. 仍然无法确认的问题

一个 Agent 完成后**不停顿**，继续下一个 Agent；全部完成后直接进入 Round 4。
