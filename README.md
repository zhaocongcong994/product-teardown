## 这是什么

AI 产品像一个黑盒：你看得见界面，看不见里面的 Agent 怎么分工、System Prompt 怎么写、数据怎么流转。product-teardown 是一套交给 AI 助手使用的 Skill：它**实际操作目标产品并逐张截图**，把证据整理成六轮交付物——用户旅程图、Agent I/O 契约、功能等价的 System Prompt、产品全景架构图，最后汇总成一个可直接打开的 HTML 报告。

<table>
  <tr>
    <td width="33%" valign="top">
      <h3>🔍 有理有据</h3>
      所有结论标注三级证据：【页面事实】【合理推断】【尚未确认】。页面没展示的工具名用功能性命名并注明"非官方工具名"，后端实现永远不被写成已确认事实。
    </td>
    <td width="33%" valign="top">
      <h3>🛡️ 只看不改</h3>
      全程只读取证：不触发产品的生成、发布、删除、购买、充值、覆盖资产操作；不查看或输出 Cookie、Token、密码等敏感信息。
    </td>
    <td width="33%" valign="top">
      <h3>📦 六轮标准交付</h3>
      从截图校验到汇总报告，每轮有固定交付物和详细提示词；Agent 说"已完成"不算完成，必须核对画布/资产/状态。
    </td>
  </tr>
</table>

**你可以用它：**

- 拆解一个竞品 AI 产品，弄清它的 Agent 架构和提示词思路
- 复刻某款产品的设计：照着交付物重建用户旅程和 Agent 分工
- 给自己的产品做一次"外部视角"体检，找出旅程断点和状态冲突

## 怎么用

> **前提：** 需要能实际操作目标产品并截图的工具能力（见下），并把本目录装进 AI 助手的 skills 目录或让它直接加载 `SKILL.md`。

**① 跟 AI 说一句**，例如：

> 「用 product-teardown 拆解这个产品：<名称>，web 端。」

**② 截图采集（Round 0）**：AI 会按决策树选采集方式——

| 目标产品的形态 | 采集方式 |
| -------------- | -------- |
| Web 网页 | 浏览器操作工具（如 kimi-webbridge）自动操作 + 截图 |
| 微信小程序 | 微信开发者工具模拟器 + 系统截图，或 Mac 版微信窗口 + `screencapture` |
| Mac 桌面 App | 系统截图 + 系统级自动化（半自动，可靠性较低，需你配合） |
| 以上都没有 | AI 会明确提醒并停下，等你提供截图或装好工具 |

每张截图强制校验：确认页面已响应 → 回读检查内容 → 与已有截图去重 → 按 `序号-阶段-动作.png` 规范命名。采集完成后得到 `拆解图片汇总/` 和 `图片清单.csv`。

**③ 六轮拆解自动推进**：每轮开始时 AI 读取对应的 references 提示词严格执行。

| 轮次 | 交付物 |
| ---- | ------ |
| Round 1 用户旅程图 | 用户旅程证据表 + `用户旅程图.html` |
| Round 2 Agent 契约 | `Agent契约.html`（每个 Agent 的输入/输出/状态） |
| Round 3 System Prompt | 每个 Agent 一份 `<Agent名>-SystemPrompt.html`（功能等价版） |
| Round 4 全景架构图 | `产品全景架构图.html`（独立交付） |
| Round 5 拆解汇总 | `拆解汇总.html`（总入口） |

**停顿规则**：只有 Round 1 完成后会停下等你确认旅程图无误；之后 Round 2→5 连续执行，中间不停。

**成功标准**：`AI/<产品名>/` 目录下六类交付物齐全，每个 HTML 都能在浏览器直接打开，关键结论都能回溯到某张截图。

优秀案例（谛听 web 端/小程序端、OiiOii）的结构与深度参考见 [examples/README.md](examples/README.md)。

## 能拆什么

- ✅ Web 网页产品（有浏览器操作工具时全自动）
- ✅ 微信小程序（需微信开发者工具或 Mac 版微信配合）
- 🧩 Mac 桌面 App（半自动，需用户配合截图）
- ❌ 没有截图能力也没有截图时无法进行——这是设计如此，宁缺毋滥

拆解范围默认覆盖完整主流程，并尽量包含用户修改/纠偏、生成失败、余额不足、中断等分支场景。

## 常见问题

<details>
<summary><b>没有浏览器操作工具能拆吗？</b></summary>

<br>

可以手动模式：你自己操作产品并截图交给 AI，它从 Round 0 的校验环节（0.3）接着做。完全没有任何截图时，AI 会明确提醒并停止等待——它不会凭空编一份拆解。

</details>

<details>
<summary><b>拆解会动到我的账号数据吗？</b></summary>

<br>

不会。全程只读取证，明确禁止触发产品的生成、重新生成、发布、删除、购买、充值、覆盖资产操作，也不查看或输出 Cookie、Token、密码、鉴权头和个人敏感信息。

</details>

<details>
<summary><b>结论的"三级标注"是什么意思？</b></summary>

<br>

- **【页面事实】** 截图里直接可见的内容
- **【合理推断】** 由多条页面事实推导出来的判断
- **【尚未确认】** 证据不足，如实标注不知道

Round 4 架构图使用对应的【已确认】【建议设计】【未知】层级。前端无法确认的后端实现（数据库、消息队列、云服务）永远不会写成事实。聊天状态与画布/资产状态冲突时，两边都记录，不替你选一个。

</details>

<details>
<summary><b>System Prompt 是原样抄出来的吗？</b></summary>

<br>

不是。原 prompt 不可得，交付的是**功能等价版**：基于截图证据推导出"要达到同样的页面行为，这个 Agent 的 System Prompt 需要包含哪些指令"，并同样标注证据等级。

</details>

<details>
<summary><b>为什么 Round 1 之后要停下确认？</b></summary>

<br>

旅程图是后续所有轮次的地基——用户路径和分支确认错了，契约、Prompt、架构会跟着错。确认无误后再让 AI 连续跑完，避免中途反复返工。

</details>
